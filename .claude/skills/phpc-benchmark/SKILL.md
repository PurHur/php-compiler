# php-compiler benchmarks vs Zend (php-src)

Two benchmark surfaces, different questions:

| Surface | Question | Refresh command |
|---|---|---|
| `benchmarks/` + `script/bench.php` | **Compute throughput** (Ack, fibo, mandelbrot): Zend vs VM vs JIT vs native binary | `./script/docker-exec.sh -- bash -lc 'PHP_8_2=$(command -v php) php script/bench.php'` |
| `examples/README.md` table (`script/rebuild-examples.php`) | **Startup + small-request wall time** per example incl. `phpc build` compile cost | `./script/docker-exec.sh -- bash -lc './script/rebuild-examples.php'` |

## Ground rules for honest numbers

- **Quiet machine only** — never benchmark while a gate/spine link runs (single benchmark run saturating 1 core is fine; a fast gate saturates all).
- **Pinned env only** (Docker PHP 8.2 + LLVM 9): host PHP version changes Zend columns.
- Output-verify before timing: every runtime must produce identical output or its column is `n/a` — a fast wrong binary is not a benchmark (see #15632: binaries that exit 0 mid-output look "fast").
- AOT columns are `n/a` while the build/probe fails (#15642 class); never hand-fill timings the current master cannot reproduce — the `check-rebuild-examples-*-row` gates enforce this for examples.
- Record environment (PHP version, LLVM availability, iterations) next to the table; commit table + environment line together.

## Interpreting the columns

- `Zend X.Y` — php-src CLI, the baseline users compare against.
- `bin/vm.php` — compiler's interpreter; expect ~5–10× slower than Zend on startup-dominated scripts (it boots the compiler in PHP), can win on tight loops it lowers well.
- `bin/jit.php` — MCJIT: pays LLVM compile at startup, then native speed; only wins when compute time dominates the ~0.2 s compile.
- `phpc build` — one-time compile cost (seconds; see the compile-split issue for stage timings).
- `native run` — the story: standalone binary, no Zend at runtime; for compute-bound code expect ≥10× faster than Zend, and ~ms startup vs Zend's ~8 ms.

## Claims discipline

Quote speedups only as *"X× on <benchmark>, <env>, <date>, table in <file>"* — the repo's public pages must trace every number to a committed table generated by one of the two commands above.
